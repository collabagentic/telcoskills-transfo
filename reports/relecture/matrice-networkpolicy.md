Résumé :
- Confirmées : 11 affirmations (comportement par défaut, isolation, default deny, élément `{}`, plugin réseau, protocoles, IP éphémères, SCTP/AMF, port 38412 via IANA).

## Verdict sur l'épreuve

- Raisonnement attendu : soutenu par la source Kubernetes pour ses quatre éléments (défaut ouvert, isolation par policy sélectionnante, plugin sans effet, `{}` autorise tout). Une réserve : « seul le trafic qu'elle autorise » doit devenir « seul le trafic autorisé par les policies qui le sélectionnent » (additivité), et le trafic du nœud reste autorisé.
- Le 38412 en SCTP de l'énoncé n'est pas soutenu par la `epreuve.source` (qui ne cite que Kubernetes) : le cas suppose un fait venant de l'IANA. Ajouter l'IANA (ou la TS 38.412) dans `epreuve.source`, ou fournir le port dans l'énoncé.
- Piège sous-exploité : la page exige un plugin CNI qui gère SCTP. Pour un cas AMF/SCTP, c'est le piège le plus pertinent ; à ajouter ou à substituer à l'un des deux.
- Réalisme pour un architecte télécom : correct dans l'ensemble (AMF, SCTP, matrice de flux). Réserves : le pair de l'AMF est un gNB externe, donc des IP (`ipBlock`) plutôt que des labels côté source ; l'accès SCTP depuis l'extérieur passe en pratique par un mécanisme d'exposition dont les sources ne parlent pas (non vérifié, ne pas l'affirmer dans la fiche).
- Verdict : acceptable après correction de la source (IANA) et de la nuance d'additivité.
